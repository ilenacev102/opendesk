# ServiceDesk VISION — каде оди платформата

> Статус: работна визија v1 (2026-09-28). Секоја тврдба мора да стане проверлива: команда, тест или метрика.

## 1. Слика за 12 месеци

Локална, доверлива, досадно-стабилна платформа за ИТ евиденција во мала/средна фирма:

- Еден извор на вистина за уреди, луѓе, локации, лиценци, договори.
- Секоја промена е следлива: кој, кога, што, зошто (audit trail) + документ (DOCX/PDF).
- Пописот се прави со телефон за еден ден, не за една недела.
- Инцидентите имаат рокови, SLA и ескалација — ништо не тоне тивко.
- Увозот (CSV, Intune, heartbeat, SNMP, LDAP) никогаш не гази задолжена опрема и секогаш има preview пред запис.
- Backup/restore е докажан, не ветен: nightly snapshot + restore-проба.

## 2. Принципи (редоследот е важен)

1. **Точност пред брзина.** Погрешна евиденција е полоша од бавна.
2. **Preview пред запис.** Ниеден bulk-увоз не пишува директно.
3. **Трансакција или ништо.** Уред + трансакција + историја одат заедно (`BEGIN IMMEDIATE`) или се враќаат.
4. **Најмалку привилегии.** `citac` чита, `magacioner` работи, `admin` администрира. SSO создава само `citac`.
5. **LAN-доверба, интернет-скепса.** Не се изложува директно на интернет; secrets само во env.
6. **Досадна технологија.** Flask + SQLite default, Postgres опција. Без нов стек без ADR.

## 3. Цели со бројки (SLO)

| Област | Цел (12м) | Проверка |
|---|---|---|
| Достапност (LAN) | 99,5% во работно време | health + лог |
| Одговор `/`, `/devices` (p95, LAN) | < 300ms при 500 уреди | load-проба |
| Попис | 200 уреди / час по човек со скенер | теренска проба |
| SLA breach видливост | 100% пробиени рокови означени + digest | тест |
| Backup | nightly snapshot, restore-проба неделно | runbook + лог |
| Suite | зелен на секој merge (440 теста) | CI |

## 4. Што НЕ правиме

- Нема јавен интернет-хостинг без reverse-proxy, WAF, SSO-enforce и надворешен pentest.
- Нема daemon-увоз без preview (IMAP/Intune/LDAP остануваат рачен trigger).
- Нема нова база/queue/framework без ADR и миграциски план со rollback.
- Нема пишување во LDAP/AD (read-only засекогаш).
- Нема верба во клиентот: heartbeat/SNMP/CSV се недоверливи влезови.

## 5. Новитети што ја прават разликата

- **Ops конзола:** една табла — breach SLA, гаранции 30/60/90, трошоци, MTTR.
- **PWA попис:** камера + offline ред, `/popis/<pid>/scan`.
- **Discovery без гажење:** reconcile (new/match/conflict), задолжените уреди недопрени.
- **Ticketing Pro:** SLA работни часови, ескалација без assignee-steal, коментари, прилози, KB-врски, дупликати, email-to-ticket со Message-ID dedupe.
- **CMDB по уред:** `/cmdb/<id>` — уред + сопственик + лиценци + договори + резервации + барања + инциденти.

## 6. На што внимаваме најмногу

1. **Интегритет под конкуренција:** ID-генерација во трансакција, heartbeat-трки, WAL + busy_timeout.
2. **Документи:** DOCX секогаш, PDF само со LibreOffice; шаблони верзионирани.
3. **Auth-матрица:** секоја рута има тест кој смее/не смее (`test_auth_matrix`).
4. **CSP/nonce:** ниту еден inline-скрипт без nonce.
5. **Податоци:** Postgres mover со dry-run + verify (`services/pg_mover.py`).

## 7. Како мериме напредок

- Секој спринт завршува со демо + метрика, не со „завршивме задачи".
- `ROADMAP.md` е извршниот план. `ARCHITECTURE.md` е техничката вистина. `CHANGELOG.md` е доказот.
